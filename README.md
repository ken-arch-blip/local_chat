# Huddle

A small, self-hosted chat server for you and your friends — text channels, voice
rooms, and DMs, with a member list that only ever contains people you invited.

One Node process, one SQLite file, no external services — and **no native
dependencies**, so `npm ci` never needs a compiler.

---

## What's in it

**Chat**
- Servers with as many text channels as you like
- Real-time messages over a WebSocket (no polling)
- Edit and delete your own messages; server owners can delete anyone's
- Emoji reactions and inline replies
- Typing indicators, date separators, message grouping
- Link detection, `inline code`, and `@username` mention highlighting
- Direct messages, sorted by whoever spoke last
- Unread badges per channel and per server
- Browser notifications for DMs and mentions when the tab is in the background

**Voice**
- Voice channels using peer-to-peer WebRTC (mesh)
- Mute, deafen, and a green ring around whoever's talking
- Audio goes browser-to-browser; the server only relays signalling

**Accounts**
- Username + password, bcrypt-hashed
- 30-day session in an httpOnly cookie
- Editable display name, status, and avatar colour
- Servers are invite-code only

**Look and feel**
- Black and cream, not a Discord reskin: squared monogram tiles instead of
  circular avatars, hairline rules instead of filled panels, a serif for
  display type, and cream-on-black inversions for anything primary
- Motion throughout — staggered list entrances, message arrival animations,
  skeleton shimmer while a channel loads, animated typing dots, a breathing
  ring around whoever is speaking, hover responses on every control
- Entry animations are gated to real context changes, so the sidebar does not
  re-animate every time someone's presence ticks
- Everything decorative collapses under `prefers-reduced-motion`

**Landing page**
- Parallax marketing page built with [Locomotive Scroll](https://locomotivemtl.github.io/locomotive-scroll/)
- Sticky app mock that plays through three scenes as you scroll
- Respects `prefers-reduced-motion`, plus a manual toggle in the footer
- Smooth scroll disabled on touch devices for native feel

## Running it locally

```bash
npm install
npm start
```

Requires **Node 22.5 or newer** — the database layer uses the built-in
`node:sqlite` module. Node 24+ is recommended, where it is no longer flagged
as experimental (on Node 22 you'll see a one-line experimental warning at boot).

Open http://localhost:3000. The landing page is at `/`, the app at `/app.html`.

For development with auto-restart:

```bash
npm run dev
```

The database lands in `./data/huddle.db`. Delete that file to start fresh.

## Deploying to Render

1. Push this repo to GitHub.
2. In Render, **New → Blueprint**, point it at the repo. It reads `render.yaml`.
3. Deploy.

`SESSION_SECRET` is generated by Render and kept stable across deploys — that's
what keeps everyone signed in. If you set it yourself, don't change it later or
every session is invalidated.

### About the disk

SQLite needs somewhere durable to live. `render.yaml` mounts a 1 GB disk at
`/var/data` and points `DATA_DIR` at it. **Disks require a paid instance type.**

On the free plan, delete the `disk:` block and the `DATA_DIR` env var. Everything
still works, but the database is wiped on every deploy and whenever the free
instance spins down. Fine for testing, not for keeping your history.

### Voice on a hosted deployment

The bundled STUN servers cover most home networks. If two people genuinely can't
hear each other, they're probably both behind symmetric NAT and you'd need a TURN
server — add one to the `ICE` config at the top of `public/js/app.js`.

## Environment variables

| Variable | Default | What it does |
| --- | --- | --- |
| `PORT` | `3000` | Port to listen on. Render sets this for you. |
| `SESSION_SECRET` | random per boot | Signs session tokens. **Set this in production** — a random value per boot means everyone is logged out on every restart. |
| `DATA_DIR` | `./data` | Where `huddle.db` lives. |
| `NODE_ENV` | — | Set to `production` to mark the session cookie `Secure`. |

## Using it

1. Create an account.
2. Hit **+** in the left rail → **Create** → name your server.
3. Open the server menu (the **⌄** next to the server name) and copy the invite code.
4. Send that code to a friend. They create an account, hit **+** → **Join**, paste it.

Keyboard: `Enter` sends, `Shift+Enter` adds a newline, `↑` on an empty box edits
your last message, `Escape` cancels an edit.

## Notes and limits

- Voice is a full mesh, so it's comfortable up to roughly 6–8 people in one room.
  Beyond that everyone's upload bandwidth starts to hurt.
- No file or image uploads yet. Links to images render as links, not previews.
- No roles or permissions beyond "server owner can delete channels and messages".
- Messages are capped at 2000 characters; channels load 50 at a time.

## Tests

With the server running on port 3000:

```bash
node scripts/smoke.js http://localhost:3000
```

That covers auth, permissions, messaging, replies, edits, reactions, deletes,
DMs, typing relay and the full voice signalling handshake.

The UI pass drives two real browsers against the running app:

```bash
npm i -D playwright && node scripts/uicheck.js
```
